# 💡 Рекомендации по улучшению RAG сравнения

## 🎯 Проблема

Текущие вопросы о RAG являются **общеизвестными**, и модель YandexGPT уже знает ответы из своей базы знаний. Поэтому RAG не даёт существенного преимущества.

## ✅ Решение

Чтобы RAG **реально показал свою ценность**, нужно:

### 1. 📚 Добавить специфичные документы

**Лучшие варианты:**

- ✅ **Ваш README.md** из проекта AI-Advent-Challenge-RAG
- ✅ **Внутренняя документация** по вашим проектам
- ✅ **Спецификации API** (Yandex GPT, Yandex Embeddings)
- ✅ **Свежие статьи 2024-2025** (которых модель не знает)
- ✅ **Корпоративная информация** (внутренние процессы, контакты)

**Пример структуры:**
```
documents/
├── project_readme.md          # README вашего проекта
├── yandex_api_docs.md         # Документация API
├── team_guidelines.md         # Внутренние гайды
└── recent_llm_news_2025.txt   # Свежие новости
```

---

### 2. ❓ Придумать лучшие вопросы

#### 👎 Плохие вопросы (модель уже знает)

```kotlin
"Что такое RAG?"
"Как работает косинусное сходство?"
"Что такое embedding?"
```

#### 👍 Хорошие вопросы (специфичные для ваших документов)

```kotlin
val questions = listOf(
    // Про ваш проект
    "Какие команды доступны в консоли AI-Advent-Challenge-RAG?",
    "Какой размер чанков и overlap используется в TextChunker?",
    "Какие файлы нужно создать для конфигурации Yandex API?",
    
    // Про API
    "Какой endpoint используется для text-search-doc в Yandex Embeddings API?",
    "Какие параметры нужны для CompletionOptions в YandexGPT?",
    
    // Про свежие данные
    "Какие новые функции появились в YandexGPT в 2025 году?",
    "Какой размер вектора embeddings использует text-search-doc/latest?",
    
    // Про внутренние процессы
    "Какой порядок действий для добавления нового сервиса в RAG проект?"
)
```

---

### 3. 📋 Пример создания специализированного документа

**Создайте `documents/project_info.md`:**

```markdown
# AI Advent Challenge RAG - Информация о проекте

## Команды консоли

- `index documents/` - Индексировать папку с .md/.txt файлами
- `search <текст>` - Семантический поиск
- `compare` - Сравнить RAG vs без-RAG
- `stats` - Показать статистику

## Параметры TextChunker

- **Chunk size**: 1000 символов
- **Overlap**: 200 символов
- **Min chunk size**: 100 символов

## API конфигурация

Создайте файл `local.properties`:
```
yandex.api.key=AQVN...
yandex.folder.id=b1g...
```

## Используемые модели

- **Embeddings**: `text-search-doc` (для документов), `text-search-query` (для запросов)
- **Generation**: `yandexgpt/latest`

## Архитектура проекта

```
src/
├── client/
│   ├── YandexEmbeddingClient.kt  # Клиент для embeddings
│   └── YandexGptClient.kt        # Клиент для генерации
├── services/
│   ├── IndexService.kt           # Создание индекса
│   ├── SearchService.kt          # Семантический поиск
│   ├── TextChunker.kt            # Разбиение на чанки
│   └── RagComparisonService.kt   # Сравнение RAG
└── models/
    ├── DomainModels.kt           # Основные модели
    ├── GptModels.kt              # API модели
    └── Comparison.kt             # Модели сравнения
```
```

**Затем задайте вопросы:**

```kotlin
val questions = listOf(
    "Какие команды доступны в консоли AI-Advent-Challenge-RAG?",
    "Какой overlap используется в TextChunker?",
    "Какие файлы находятся в папке services/?"
)
```

---

## 📊 Ожидаемые результаты

### Без RAG:
Модель ответит **общими фразами** или скажет, что не знает точных деталей.

### С RAG:
Модель даст **точный ответ** с ссылкой на источник:

> "В консоли AI-Advent-Challenge-RAG доступны следующие команды: index, search, compare, stats, exit [источник: project_info.md]."

---

## 🔧 Как применить

1. Создайте файл `documents/project_info.md` с информацией о вашем проекте
2. Обновите список вопросов в `Main.kt`:

```kotlin
val questions = listOf(
    "Какие команды доступны в консоли?",
    "Какой размер чанков используется?",
    "Какие модели Yandex используются?",
    "Какая структура папок в проекте?",
    "Какие классы отвечают за работу с API?"
)
```

3. Переиндексируйте: `index documents/`
4. Запустите: `compare`

---

## ✨ Резюме

✅ **RAG поможет**, когда:
- Вопросы **специфичны** для ваших документов
- Документы содержат **уникальную информацию** (которой нет в базе знаний модели)
- Нужны **точные ссылки** на источники

❌ **RAG не поможет**, когда:
- Вопросы **общеизвестные** ("Что такое RAG?")
- Модель **уже знает** ответ из своей базы знаний
- Документы не содержат релевантной информации
