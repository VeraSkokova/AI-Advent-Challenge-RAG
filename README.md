# 🎯 Day 18: RAG Reranking & Relevance Filtering

В рамках 18-го дня челленджа мы переходим от **Naive RAG** (простой векторный поиск) к **Advanced RAG**. Реализована система двухэтапного поиска с переранжированием результатов (Reranking) для повышения точности ответов и снижения галлюцинаций.

## ⚠️ Проблема базового поиска
Векторный поиск (Cosine Similarity) отлично находит семантически близкие тексты, но имеет недостатки:
1.  **Ложные срабатывания:** Может найти текст с похожими словами, но другим смыслом (например, кулинарный "чанкинг" вместо IT-термина).
2.  **Низкая точность:** Высокий векторный скор не всегда гарантирует, что в тексте есть прямой ответ на вопрос.
3.  **Шум в контексте:** Передача нерелевантных кусков в LLM ухудшает качество генерации ("Lost in the Middle").

## 🛠 Реализованное решение

Мы внедрили **Reranking Pipeline**, который работает в два этапа:

### Этап 1: Retrieval (Поиск)
Быстрый отбор кандидатов (Top-K) из векторной базы данных на основе косинусного сходства (`Vector Score`).

### Этап 2: Reranking & Filtering (Переранжирование)
Отобранные кандидаты проходят проверку одним из двух методов:

#### 1. Threshold Filtering (Фильтрация по порогу)
*   **Логика:** Жесткое отсечение всех чанков, чей `Vector Score` ниже заданного порога (по умолчанию `0.45`).
*   **Плюсы:** Очень быстро, не требует вызовов LLM.
*   **Минусы:** Может отсеять полезные документы, если векторный скор был занижен.

#### 2. LLM Reranking (Умное переранжирование)
*   **Логика:** Каждый кандидат отправляется в YandexGPT с просьбой оценить его полезность для вопроса по шкале от `0.0` до `1.0`.
*   **Hybrid Score:** Итоговый рейтинг рассчитывается по взвешенной формуле, где мнение LLM доминирует:
    ```
    HybridScore = (VectorScore * 0.3) + (LLMScore * 0.7)
    ```
*   **Плюсы:** Понимает глубокий контекст, фильтрует "шум", поднимает неочевидные, но верные ответы.
*   **Минусы:** Медленнее и дороже (требует токенов).

## 🚀 Новые команды CLI

В `Main.kt` добавлены две команды для работы с реранкером:

### `rerank`
Интерактивный режим для проверки одного запроса.
*   Показывает результаты базового поиска.
*   Показывает результаты после Threshold-фильтрации.
*   Показывает результаты после LLM-переранжирования с детализацией (Vector Score vs Hybrid Score).

rerank
🔍 Введите запрос: Что такое self-attention?
🎚️ Введите порог: 0.45
...

text

### `compare-rerank`
Автоматический бенчмарк системы.
*   Прогоняет набор из 10 тестовых вопросов через три стратегии (Baseline, Threshold, LLM Rerank).
*   Сравнивает метрики качества и генерируемые ответы.
*   Формирует детальный отчет `RERANKING_REPORT.md` с таблицами, дельтами скоров и маркерами эффективности (🚀/📉).

compare-rerank

✅ Сравнение завершено! Отчёт сохранён в RERANKING_REPORT.md

## 📂 Структура изменений

*   `models/Reranking.kt` — модели данных для результатов реранкинга (`RerankResult`, `RerankingMetrics`).
*   `services/RerankingService.kt` — основная логика:
    *   `filterByThreshold()` — простая фильтрация.
    *   `rerankWithLLM()` — оценка через YandexGPT API, парсинг скора и расчет Hybrid Score.
*   `services/RerankingComparisonService.kt` — движок для проведения бенчмарков и генерации Markdown-отчета.

## ⚙️ Конфигурация и Настройка

Для улучшения качества реранкинга можно настраивать следующие параметры:

1.  **Threshold (Порог):** Рекомендуемое значение `0.45`.
    *   Ниже — больше шума.
    *   Выше — риск потерять информацию.
2.  **Веса формулы:** Настраиваются в `RerankingService.kt`. Текущая конфигурация (0.3/0.7) оптимизирована для того, чтобы LLM могла "спасать" документы с низким векторным сходством.
3.  **Top-K:** Для максимальной эффективности рекомендуется увеличить `topK` на этапе поиска (до 15-20), чтобы дать реранкеру больше кандидатов на выбор.
